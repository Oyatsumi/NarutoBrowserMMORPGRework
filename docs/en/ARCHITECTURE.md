# Code architecture

The game is **procedural** PHP with no framework, in the style of late-2000s browser games.
Each `.php` file at the root is a "page" (or a set of actions) and decides what to do from the `do` URL
parameter. This was kept on purpose: version 4.0 refactored and documented the code without changing the
author's style.

## Request lifecycle

```
navegador ──► index.php?do=gotown:3
               │ include lib.php        (helpers, conexão, tratamento global da entrada)
               │ include cookies.php    (checkcookies() valida o cookie e devolve $userrow)
               │ doquery("SELECT * FROM {{table}} ...", "control")  → $controlrow
               │ roteamento: if ($do[0] == "gotown") { include('towns.php'); travelto(3); }
               ▼
             função da ação monta $page (string HTML / heredoc)
               ▼
             display($page, "Título")   (lib.php)
               ├─ templates/primary.php   layout geral (topo, colunas, rodapé, JavaScript)
               ├─ templates/leftnav.php   mini mapa, direção, cidades, mensagens, histórico
               ├─ templates/rightnav.php  personagem, barras, equipamentos, mochila, jutsus
               └─ parsetemplate(): troca {{chave}} pelos valores e envia a página
```

In short: the browser requests `index.php?do=...`; `lib.php` loads helpers, the connection and global input
handling; `cookies.php` validates the cookie and returns `$userrow`; the `control` row is loaded into
`$controlrow`; the router includes the right file and calls the action function, which builds `$page`
(an HTML string / heredoc); `display()` wraps it in the layout templates (`primary`, `leftnav`, `rightnav`) and
`parsetemplate()` replaces each `{{key}}` with its value.

Actions that only change data (buying, walking, storing an item...) write to the database and do
`header("Location: ...")` back to the right page, sometimes with `?conteudo=message` to show a notice.

## Conventions

- **Database**: `doquery("SELECT ... FROM {{table}} WHERE ...", "users")` — `{{table}}` becomes `prefix_users`
  (prefix defined in `config.php`). Results are read with `mysqli_fetch_array`.
- **User input**: `lib.php` applies `addslashes` + `htmlspecialchars` to all of `$_GET`, `$_POST` and
  `$_COOKIE` right at the start (the game's original pattern). Text can go inside quotes in SQL and be shown on
  the page; numbers always go through `intval()`/`pegarint()`.
- **Templates**: `templates/*.php` define `$template` with a `FIMDOTEMPLATE` heredoc; the `{{field}}` markers
  are filled by `parsetemplate($template, $array)`.
- **Include-only files** (`fight.php`, `explore.php`, `towns.php`, `funcoesinclusas.php`...) start with
  `if (!defined('NARUTO_RPG')) ...` and do nothing if opened directly in the browser.
- **Player state** lives entirely in the player's row of the `users` table — including text lists in the `a,b,c`
  format (see [DATABASE.md](DATABASE.md)). There is no server-side session.
- Comments and identifiers are in Portuguese; displayed text goes through `t()`/`tf()` (see [Languages](#languages-i18n)).

## Villages and terrains (data, not code)

- `cidadesconteudo.php` holds the village rules read from `naruto_towns`: `dadosdacidade()`, `cidadetemservico($town, "loja")`,
  `cidadesecreta()`, `vilasnatais()`, `vilanataldoalinhamento()` (used by fight.php and admin), `alinhamentodoregistro()` /
  `opcoesvilasnatais()` (registration), `cabecalhodacidade()` (title image or text) and `conteudo()` (services panel).
  towns.php, graduacao.php, senjutsu.php and jutsudebusca.php check the `tem_*` columns instead of ids.
- `lang/en/conteudo_vilas_banco.php` is a translation file that reads `name_en`/`kage_en`/`descricao_en` from the database,
  so `t($townrow["name"])` translates admin-created villages on every screen.
- `funcoesterreno.php`: `terrenodacasa()`, `nomesdosterrenos()`, `nomeexibidoterreno()` and `terrenosdoinimigo()`; used by
  the minimap and by `escolhermonstro()` (fight.php), which filters enemies by the `monsters.terrenos` column.
- `templates/minimap.php`: `terrenodacasa($lat, $lon)` picks each tile's ground from `naruto_terrenos` (highest priority;
  coordinate jittered ±2 by a fixed hash for ragged edges).
  Each 30x30 tile uses pieces from `images/terreno/` (`fundodacasa()`): ground `NAME_0..3.png` picked by hash, edges
  `NAME_b_{n,s,l,o}` and corners `NAME_c_{no,nl,so,sl}` of a higher-priority neighbour (ragged dithered mask) and a biome
  decoration `deco_NAME_K.png` (only on tiles without town/NPC/player). Generated from `images/terreno_NAME.jpg` by
  `tools/gerar_tiles_terreno.py` (Pillow + numpy).

## Communication between pages without sessions

- **`users.pagina`** stores the player's last viewed page (written by `templates/getheader.php`);
  quick actions (unequip, backpack, message) send the player back there.
- **`users.mainmsg`** is a "one-shot" message: the action writes it, the next page shows the floating window
  (`templates/mostrarmainmsg.php`) and clears the field.
- **Trades** are a protocol stored in both players' rows; the waiting screens use `<meta refresh>`.
- **PvP duels** (`users.php?do=batalha1` = lobby, `do=duelo` = fight) live in the `duelos` table. Every action opens a
  transaction that locks the duel row and then both players (ascending id); forms carry the turn number, so double
  clicks or two tabs cannot act twice. The 60 s turn clock is checked lazily on any page load of either player
  (timeout = lose the turn; 3 timeouts = defeat). Full rules in the "Duelo PvP" comment block of `users.php`.
  **Jutsus in duels** (and in open-world PvP, which reuses `dueloacao()`): state in `duelos.jutsuestado` (the JSON from
  `funcoesjutsus.php`, sides `1`/`2`). Types 1/2/6 go through `aplicarjutsu()`, 4/5 through `jutsuaplicarefeito()`; jutsu damage
  still passes +Defense, guard and `jutsureduzirdano()`; attacks use `jutsumultdano()`, crit focus and dodge buffs. A round = 2
  turns: after every even turn `dueloticar()` runs `jutsufimdoturno()` (damage over time also stops at 1 HP = defeat). A stunned
  player loses the turn automatically in `duelofimdavez()` (counts as played, not as a timeout). Cooldowns are enforced
  server-side and shown disabled in the select; status icons sit over the avatar (`cartaodojogador(..., $icones)`).

## Items, combat bonuses and drops

- **Up to 3 bonuses per item**: `items.special`, `special2`, `special3` and `drops.attribute1`, `attribute2`, `attribute3`
  (`attribute,value` format, `X` = empty). Equipping/unequipping goes through `bonusdoitem()`/`bonusdodrop()`
  (`funcoesinclusas.php`); the shop (`towns.php` buy3) adds/removes all three fields. The column whitelist lives in
  `atributovalido()` and in `admcodigoespecial()` (admin.php).
- **Combat bonuses** (new `users` columns, summed by equipment; caps in `bonuscombate()`):

  | Column | Effect | Formula / where |
  |---|---|---|
  | `critico` | critical % | if the old excellent hit (rand(1,150) <= sqrt(Strength) + 2% Determination) fails, `rand(1,100) <= critico` also doubles damage; max 50 (fight.php) |
  | `esquiva` | dodge % | if the old dodge (rand(1,150) - 2% Agility <= sqrt(Dexterity)) fails, `rand(1,100) <= esquiva` also dodges; max 40 (turnodoinimigo) |
  | `regenhp` | HP per step | every tile walked: `currenthp = min(currenthp + regenhp, maxhp)` (explore.php andarumacasa) |
  | `economiachakra` | % less chakra | cost = `ceil(CH x (100 - savings)/100)`, minimum 1, savings max 50 (`custochakra()`; fight.php and heal.php) |

- **Per-enemy drops** (`naruto_monster_drops`: `monster_id`, `drop_id`, `chance_percent`): on victory (no level up),
  `sortreardrop()` tests the rows in the order they were linked (monster_drops.id; the first linked is rolled first) with chance `chance_percent x M`, where
  `M = 25 x (1 + 2% Luck) / (25 - 22% Drop Chance)` — the same factor the old rule gave Luck and Drop Chance. The first
  row that hits is the drop (only one fits, in `users.dropcode`). Enemies without rows use the old rule (1 in 25, any
  drop with `mlevel` <= level; mission drops with `mlevel` >= 100 are excluded).
- **Consumable drops** (`drops.consumivel` = `hp,50` / `mp,40`): when taken they go only to the backpack as a regular
  potion (`name,hp,50,1`), used by `backpack.php` like the existing potions.
- Victory and "take drop" lock the player (`START TRANSACTION` + `SELECT ... FOR UPDATE`) and write Ryou/experience
  relatively (`gold=LEAST(gold+x, ...)`), so parallel requests cannot duplicate or undo anything.

## Configurable jutsus and scrolls
- **`spells` table**: besides `type` (1 heal, 2 damage, 3 sleep, 4 +damage, 5 +defense, **6 support**), `mp`, `attribute` and
  `elemento`, each jutsu may have `golpes` (hits, 1-4), `roubovida` (life steal %), an **extra effect** (`efeito`, `efeito_valor`,
  `efeito_turnos`, `efeito_chance`), `cooldown` (turns), requirements to learn from a scroll (`nivelminimo`, `classe` 0/1/2/3,
  `graduacao`) and texts `name_en`, `descricao`, `descricao_en` (translated by `lang/en/conteudo_jutsus_banco.php`, read from the
  database). With the default values an old jutsu works exactly as before.
- **Effects** (`jutsuefeitos()` in `funcoesjutsus.php`, included by `funcoesinclusas.php`): `queimadura`/`veneno` (burn/poison,
  damage per turn), `atordoar` (stun: the enemy loses its attack; not refreshed while active; immune-2 enemies are not affected),
  `escudo` (shield absorbing X damage), `buff_ataque`/`buff_defesa`/`buff_critico`/`buff_esquiva` (%), `debuff_ataque`/`debuff_defesa`
  on the enemy (%), `cura_turnos` (heal over time) and `dreno_chakra` (instant). The same effect does not stack: the strongest
  value stays and the duration is refreshed.
- **Fight state**: `users.jutsuestado` (JSON `{"efeitos": {side: {effect: {v, t, n}}}, "cd": {side: {id: turns}}}`, sides `jog`/`ini`
  in PvE). Cleared on the 1st turn, victory, death, escape and `encerrarluta()`. A round = player action → `turnodoinimigo()` (stun,
  extra dodge, `jutsureduzirdano()`: weakened attack, defense boost and shield) → `jutsufimdoturno()` (damage/heal over time,
  countdown). Physical attacks use `jutsumultdano()` and the extra crit. 12x12 icons in `images/status/` (made by
  `tools/icones_status.py`) on the enemy card (`cartaodomonstro(..., $icones)`) and under "Your effects".
- **Functions also used by duels** (`users.php`, see above): `aplicarjutsu(&$caster, &$target, $spell, &$state)` (heal, multi-hit
  damage with element and life steal, extra effect and cooldown; does not charge chakra; returns `dano`, `cura` and `msgs` in
  `i18n:` format), `jutsuaplicarefeito()` (effect only, for types 3-5), `jutsurecarga()`, `jutsuatordoado()`, `jutsubonus()`,
  `jutsumultdano()`, `jutsureduzirdano()`, `jutsufimdoturno()`, `jutsuicones()`, `jutsuestadoler()`/`jutsuestadotexto()`, `jutsudescricaoefeitos()`.
- **Learning**: by level (`levels` table, `N_spells` columns, as always) or by **scroll**: a drop with `drops.ensina_jutsu` = jutsu
  id. On victory it only goes to the backpack as `"Pergaminho: Name,jutsu,ID,1"` (never a rare variant); clicking it in the backpack
  (`backpack.php`) checks `jutsurequisitos()` (level, class, rank), saves it with `jutsuaprender()` and consumes it. A player who
  already knows the jutsu keeps the scroll (bank or trade). Scrolls never drop through the old rule (enemies without a drop table).
  Icon: `layoutnovo/equipamentos/novos/pergaminho_ELEMENT.gif` (`iconepergaminho()`, `tools/pergaminhos_elementos.py`).
- **Content**: jutsus 20-49 (15 by level, 15 scroll-only; drops 102-116 in `naruto_monster_drops` at 0.3-0.5%), generated by
  `tools/jutsus_novos.py` → `tools/jutsus_novos.sql` (used by `build_sql.py`).

## Rare item variants
- Format: a `:effect` suffix in the item **name** (`weaponname`, `slot1name`..., 1st field of `bp1..bp8`, the bank and
  trades): `Kunai:dourado`, `Kunai+2:chama`. Old items have no `:` and stay the same. Since all code that moves items
  already copies the whole name, the variant survives equip/unequip/bank/trade with no new columns; the locks
  (`SELECT ... FOR UPDATE`) of those flows cover it too.
- `funcoesinclusas.php`: `variantesitens()` (table), `separarvariante()`, `variantedoitem()`, `nomecomvariante()`,
  `sortearvariante($chance)`, `bonusvariante($name, $row, "items"|"drops")` (list of "field,value"), `nomeitemhtml()`
  (colored label), `iconeitem($id, $drop, $name, $suffix)` (variant icon if the file exists), `iconesequipados()`.
  `bonusdoitem()` already took the name; `bonusdodrop($id, $sign, $name = "")` and `conteudoexplic(..., $name = "")` got
  an optional parameter. `tnomeitem()` returns "Name ✦ Label" as plain text.
- Roll: `fight.php :: sortreardrop()` reads `monster_drops.chance_variante_percent` and stores the effect in
  `users.dropvariante` along with `dropcode`; `drop()` builds the name with the variant when the item is taken.
- Bank/shop: `funcaoitens.php :: bancobonusitem()` adds/removes the bonus; `towns.php :: buy3()` removes the bonus (and the
  refine) of the item being sold.
- Icons: `layoutnovo/equipamentos/variantes/<effect>/[drops/]<id>[d].gif`, generated by `tools/variantes_itens.py`
  (Pillow + numpy; the silhouette is separated from the tile background by flood fill from the corners).
- The `showchar`/`onlinechar` templates use `{{weaponicone}}`...`{{slot3icone}}`; `rightnav.php` builds names/icons
  in its own variables (lib.php's `display()` replaces `{{weaponname}}` with `t(name)`).

## Languages (i18n)

The game has two languages: **Portuguese (`pt`, default)** and **English (`en`)**. The code stays in Portuguese and
**the Portuguese text itself is the translation key** (gettext style). All the infrastructure is at the top of
`lib.php`.

### How the language is chosen

1. The `?idioma=pt` / `?idioma=en` parameter on any page: applies immediately and is stored in the `idioma`
   cookie (1 year, `HttpOnly`, `SameSite=Lax`).
2. Otherwise, the `idioma` cookie.
3. Otherwise, the **game's default language**, set under *General settings* in the Administrator Panel
   (column `control.idiomapadrao`).

Players switch language with the "Português | English" links (`seletoridioma()`) shown in the game **footer**, on
the **login page** and in the **Administrator Panel top bar**. `linkidioma()` builds the link so the player stays
on the same screen without repeating actions.

### Functions

| Function | What it does |
|---|---|
| `idioma()` | Code of the current language (`"pt"` or `"en"`). |
| `t("Texto")` | Returns the text in the player's language; without a translation, returns the Portuguese text. |
| `tf("Você ganhou %s Ryou.", $gold)` | Like `t()`, with values replacing `%s` (`vsprintf`). A literal `%` is written `%%`. |
| `i18n("Chave com %s", $valor)` | Builds the neutral text `i18n:Chave com %s\|valor` to **store in the database**. |
| `textoi18n($texto)` | Displays a stored text: if it starts with `i18n:`, translates the key and applies the values; otherwise returns it unchanged. |
| `seletoridioma()` | The "Português \| English" links. |
| `localizarimagens($pagina)` | Replaces images containing Portuguese text with the language's version, when one exists. |

Inside heredocs use variable functions: `$t = "t"; $tf = "tf";` and then `{$t("Texto")}`.

### Translation files

`game/lang/en/*.php` — each file returns an array `"Portuguese text" => "English text"`; every file in the folder
is loaded and merged. The key must be **exactly** the text passed to `t()`/`tf()`. Names coming from the database
(enemies, items, jutsus, villages...) are displayed with `t($row["name"])` and translated in
`lang/en/conteudo_*.php`; the database still stores the Portuguese name.

### Messages stored in the database

History, private messages and the floating window (`mainmsg`) are read later by another player whose language is
unknown at write time. They are therefore stored in the neutral format `i18n:Portuguese key|value1|value2`
(built by `i18n()`; a `|` inside a value becomes `/`) and displayed with `textoi18n()`. Older messages without the
prefix are shown as they were stored.

### Images with text

Images that contain written text (buttons, titles, menus) can have a per-language version in a subfolder named
after the language code, e.g. `images/en/`, `images/24/en/`, `layoutnovo/buttons/en/`, `layoutnovo/menuslados/en/`
and `layoutnovo/titulo/en/`, with the **same file name** as the original. `localizarimagens()` rewrites the paths in
the generated page; without a translated version, the original image is used.

### Adding a new language

1. Copy `game/lang/en/` to `game/lang/xx/` (`xx` = language code) and translate the values (the keys stay in
   Portuguese).
2. Add the language to `$idiomasdisponiveis` in `lib.php`: `array("pt" => "Português", "en" => "English", "xx" => "Name")`.
3. Optionally create translated images in `images/xx/`, `layoutnovo/buttons/xx/` etc.

The language then shows up in the selector and in the panel's default-language setting.

### Finding missing translations

With `"debug" => true` in `config.php` (test environments only), every untranslated text is written to the PHP
error log as `[traducao-faltando] text`:

```bash
grep traducao-faltando /var/log/apache2/error.log | sort -u
```

To contribute translations, see [TRANSLATING.md](TRANSLATING.md).

## Death, abandoned fights and mission jutsus
- `fight.php :: penalidademorte($level)` returns the percentages (`control.morte*`):
  `ryou = min(morteryoumax, morteryoubase + level × morteryounivel)`; `exp = min(morteexpmax, level × morteexpnivel)` % of
  the bar (`levels[level+1].N_exp − levels[level].N_exp`, never below `levels[level].N_exp`);
  `item = min(morteitemmax, level × morteitemnivel)` % chance of destroying one eligible item (`itemperdivelnamorte()`:
  common equipment or potion; never variants, scrolls or items used by missions). Up to `mortenivelseguro`, exp and item = 0.
  Defaults: level 1 → 11% Ryou; 10 → 20%/5%/2.5%; 20 → 30%/10%/5%; 40+ → 50%/20%/10%; 80 → 50%/25%/15%.
- `morrernaluta($id = 0, $reason = "luta"|"logout"|"abandono")`: transaction with `SELECT ... FOR UPDATE`; acts only if
  `currentaction='Fighting'`. Logout/abandon: `mt_rand(1,100) <= mortelutachance` → death, else the fight is cancelled.
- `users.lutaultimaacao` (UNIX) is written when a fight starts (explore.php) and on every turn; `lutasabandonadas()` runs
  from index.php. `login.php :: logout()` calls `morrernaluta(id, "logout")` and `dueloforcarderrota()` for duels.
- Missions: `mx_recompensajutsu()` picks teach / scroll / compensation; learning happens in the same UPDATE as the
  completion (`NOT FIND_IN_SET` in the WHERE). `spells.exclusivo_missao=1` is honoured on level-up, in the admin
  level/drop/jutsu editors and on the help page.


- `alquimia.php`: Alchemy 2.0 (database recipes, experiment, refine, infusion, potions, scroll copy). See [ALCHEMY.md](ALCHEMY.md).
